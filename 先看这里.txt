CC Switch / Codex 过滤层 v4
============================

适用环境
--------
1. Windows 10 或 Windows 11
2. 已安装并能正常使用 Codex
3. 已安装 CC Switch，并开启“本地代理”和 Codex 接管
4. 电脑上已有 Node.js 24 或更高版本

这个压缩包不包含 Node.js，也不需要 npm install。
脚本会优先使用系统中的 Node.js 24+；如果 Codex 运行环境中已有兼容版本，也会自动查找。

如何找到 Node.js
----------------
双击启动入口后，脚本依次检查：
1. 环境变量 CCSWITCH_FILTER_NODE 指定的 node.exe 完整路径（如果已设置）。
2. 系统 PATH 中的 node 命令；有多个版本时依次检查。
3. 当前用户下 Codex 的几个常见运行环境位置。
每个候选会检查版本，选择第一个 Node.js 24+，再用其完整路径运行服务。
双击“检查运行环境.cmd”可查看找到的路径和版本。

如果 Node 放在自定义目录且未加入 PATH，不会扫描全盘寻找。
可在 Windows 用户环境变量中新增 CCSWITCH_FILTER_NODE，值填写自己的 node.exe 完整路径。
例如 D:\tools\nodejs\node.exe，不加外层引号。
保存后需让启动入口拿到新的环境变量；注销并重新登录 Windows 后再双击即可。
详细查找路径及临时指定命令见 README.md 的“如何自动找到 Node.js”。

第一次使用
----------
1. 解压整个文件夹，不要只从压缩包中直接运行单个文件。
2. 双击“检查运行环境.cmd”，处理其中显示的注意项。
3. 完全退出 Codex。
4. 双击“打开控制面板.vbs”。它会隐藏终端并自动打开浏览器。
5. 在页面点击“启动过滤”，确认状态显示“过滤中”，再重新打开 Codex。
6. 发一条消息后，确认页面里的“已过滤请求”数字增加。

停止使用
--------
在控制页面点击“停止全部服务”。工具会恢复 Codex 原来的 CC Switch 地址，并关闭过滤层和控制页面。
随后完全退出并重新打开 Codex。

如果控制页面打不开
------------------
双击“打开控制面板.cmd”查看错误。常见原因：
- 没有 Node.js 24+
- CC Switch 没开启本地代理或 Codex 接管
- 端口 18180 / 18181 被其他程序占用
- Codex 配置使用了自定义 profile 或命令行覆盖路径

限流自动重试
------------
遇到 token rate limit、rate_limit_exceeded、too many requests 等限流错误时，最多自动重试 50 次。
优先按服务器提示的时间等待；没有提示时约按 5、10、20、40、60 秒逐步延长等待。
初次请求加 50 次重试，总共最多 51 次。持续限流时可能等待约 47 分钟或更久。
在 Codex 中点停止会取消等待与后续重试；最近日志会显示每次重试的次数和等待时间。
余额不足、鉴权失败、普通网络断开，以及已经开始返回普通事件的流不会自动重试。
重试只能等待上游恢复额度，无法增加账号或 Azure 资源的 token 配额。

重要限制
--------
- 过滤层会移除历史推理和部分绑定上游资源的历史 ID，复杂长任务的连续性可能降低。
- 不支持 Responses WebSocket 和自动 compaction。长聊天接近上限时，应先生成进度摘要，再新建聊天继续。
- 启动或停止过滤后，都应完全退出并重新打开 Codex。
- 重启电脑后，先重新启动过滤层；不再使用时先执行“停止全部服务”。
- 本工具不包含账号、API Key、CC Switch 配置或 Codex 配置。
